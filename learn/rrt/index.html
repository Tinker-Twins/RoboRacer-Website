Search on a grid

Every grid search keeps a frontier: cells it has seen but not expanded yet. BFS, Dijkstra, A* and Greedy differ in one thing only, which frontier cell comes out next.

More on grid search

BFS pops cells in rings of equal step count, so the first time the goal comes out, nothing shorter exists. It counts steps, not cost: on the Mud map it walks straight through.

Dijkstra pops the smallest cost so far, g. One cell can sit in the heap several times with different costs; if (dist[cur] < cost) continue; throws away the stale copies (crossed out in the strip under Figure 1).

A* pops the smallest f = g + h, where h estimates the cost still to go. Manhattan distance never overestimates on a 4-connected grid where every step costs at least 1, so A* returns the optimal cost while expanding far fewer cells. With h = 0 it is Dijkstra.

Greedy keeps only h. In the code that is a one-line change from A* (marked in the code panel). It rushes at the goal and expands the fewest cells, but it ignores what it has already paid: on Mud it walks straight through the expensive cells.

With V cells and E ≈ 4V edges, BFS runs in O(V), Dijkstra and A* in O(E log V) with a binary heap.

Why sample?

A grid needs one cell for every combination of state values, and a car's state has more than two numbers in it.

Sampling planners skip the grid. They drop random points into the space and join them with short, collision-checked edges, so the work grows with the number of samples instead of with the resolution to the power of the dimension.

RRT

A rapidly-exploring random tree grows from the start. Each round it picks a random point, finds the closest node, and takes one step of length η toward the point. The step stays if it hits nothing.

More on RRT

Voronoi bias. A uniform sample is closest to a node with probability equal to the area of that node's Voronoi region. Nodes on the edge of the tree own the biggest regions, so they get extended the most and the tree rushes outward.

Step size η. Long steps cover ground fast but fail more collision checks near walls; short steps squeeze through gaps but need more nodes.

Goal bias. Sampling the goal itself 5 to 10% of the time pulls the tree toward it. At 100% RRT only ever steps straight at the goal and stalls behind the first wall.

Probabilistically complete means the chance of having found a path goes to 1 as samples keep coming, if a path exists. Narrow passages make that slow: try Gap.

Collision checks. The code walks each edge in half-cell steps of the 5 cm grid. That can clip a cell corner by a few millimeters, so inflate obstacles by half the car's width plus a margin, as Lab 6 does anyway.

Jagged paths. RRT paths zigzag. Shortcut smoothing picks two waypoints and, if the straight line between them is free, drops everything in between. Find a path, then press Smooth the path.

RRT*

RRT* adds two steps. Before adding xnew, connect it through the cheapest node nearby. After adding it, let nearby nodes switch to xnew as their parent when that makes their path shorter.

More on RRT*

The radius. r = min(γ·(log n / n)1/d, rmax). It shrinks as the tree grows, so each round looks at roughly log n neighbors: few enough to stay fast, enough for the path to converge to the optimum.

Update the subtree. After a rewire, every node below the rewired one gets cheaper by the same amount. Skip that and later rounds compare stale costs. Try it under Break it.

Keep it running. RRT* is an anytime planner. Its first path is about as crooked as RRT's; the gains come from the rounds after that. Stopping at the first path throws them away.

Asymptotically optimal means the best path's cost converges to the optimal cost as the number of samples goes to infinity. RRT's cost converges too, to something worse, with probability 1 (Karaman and Frazzoli, 2011).

In Lab 6 the tree is rebuilt every scan, so each plan gets a few tens of milliseconds. A few hundred RRT* nodes already give visibly straighter paths than RRT, which pure pursuit will thank you for.

    About the code

    The grid searches are the course's BFS, Dijkstra and A* templates with walls, a zero-cost start and a parent array added so the path can be drawn. The RRT code is the course's interview solution adapted to a 5 cm occupancy grid, with RRT*'s cost update and keep-improving loop filled in. Every figure runs a JavaScript copy of the same steps, line for line, which is what lights up the code panel. The Lab 6 planner has no code here on purpose: writing it is the lab.

    Keyboard: Space play or pause, , and . previous and next step, → one round, ← back, L one line, R reset, Esc close the code. Keys act on the figure you last touched. Click a step above a figure to jump to it, and drag the History slider to go back to any earlier round.
